针对服务器进行相应的端口探测

```
sudo nmap -p- -vvv --min-rate 10000 192.168.159.91
```

针对开放的端口进行相应的服务探测

```
sudo nmap -p22,25,80,443 -A 192.168.159.91 -oG Scrutiny.txt
```

![image-20241127213823258](https://s2.loli.net/2024/11/27/FGP3kwMUo4rRjIJ.png)

针对22端口没有可以直接利用的相关openssh漏洞，针对25端口的smtp服务，我们进行下登录尝试

```
telnet 192.168.159.91 25
```

![image-20241127214408526](https://s2.loli.net/2024/11/27/rV7bLEAUqZD9Y8p.png)

我们尝试添加一个hosts文件

```
192.168.159.91    onlyrands.com
```

针对80端口的web服务进行相应的扫描工作

```
dirsearch -u http://192.168.159.91/ -w /usr/share/wordlists/dirb/big.txt -f -e php,txt,html
```



我们在页面上找到一个login的入口，点击后发现存在一个子域名，我们再添加一条hosts文件

```
192.168.159.91    teams.onlyrands.com

我们看到这个软件叫teamcity，对应的软件版本号为2023.05.4（build129421）

我们如果搜索相应的exploit，发现有个CVE-2023-42793的RCE漏洞再05.4版本被进行了修复，我们又进一步搜索，发现CVE-2024-27198 & CVE-2024-27199，前者可以实现认证bypass，后者可以RCE，我们找到一个poc来实现相应的rce，我们优先下载相应的POC

(https://github.com/W01fh4cker/CVE-2024-27198-RCE?tab=readme-ov-file)

我们尝试相应的利用脚本后，发现认证bypass能够实现，但RCE还是存在问题，我们创建admin/admin用户密码登录

![image-20241127222455077](https://s2.loli.net/2024/11/27/zfVsKnZo172wNEm.png)

![image-20241127224030008](https://s2.loli.net/2024/11/27/SiHu43vfOBGCYXl.png)

貌似存在一个debug模式没有开启，我们将相应报错进行Google搜索

（CVE-2023–42793

我们在changelog的其中一个发现了一个id_rsa文件，我们进行查看

![image-20241127231210545](https://s2.loli.net/2024/11/27/MN8vIruyTK1FEXx.png)

id_rsa密钥文件看似是可以使用的，同时这个是由Marco Tillman <marcot@onlyrands.com> 创建的，合理怀疑是否存在用户叫做marcot，我们将id_rsa复制到本地进行登录

```

![image-20241127231836711](https://s2.loli.net/2024/11/27/EgjC6nfvYD329et.png)
