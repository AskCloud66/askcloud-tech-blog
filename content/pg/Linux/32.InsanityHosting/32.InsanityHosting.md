针对目标服务器进行相应的端口扫描

```
sudo nmap -p- -vvv --min-rate 10000 192.168.108.124
```

![image-20241209215722441](https://s2.loli.net/2024/12/09/QOLenVY6iyKAIqG.png)

针对目标服务器开放端口进行相应的服务探测

```
sudo nmap -p21,22,80 -A -sV 192.168.108.124 -oG InsanityHosting.txt
```

![image-20241209215737484](https://s2.loli.net/2024/12/09/JpjyivRuD6IaozA.png)

21端口我们可以看到允许匿名登录，我们优先进行登录查看是否存在可以使用的文件

![image-20241209215919437](https://s2.loli.net/2024/12/09/izE9n1M6GJh54s3.png)

没有任何的文件内容，只有一个目录名称pub

22端口没有可以针对openssh进行利用的内容，我们把重点放到http服务80端口，我们优先针对80的服务端口开启一个扫描任务

```
dirsearch -u http://192.168.108.124
```

我们可以看到对应是mail版本，经过Google搜索，发现该版本存在一个可以利用的RCE漏洞CVE-2017-7692

```
searchsploit -m 41910.sh
```

但我们发现这个漏洞的利用是需要认证的，我们需要获取到相应的用户密码进行登录

我们根据官方的文档说明，可以看到一个登录页面，我们直接搜索bludit exploit，结果发现3.9.2版本存在RCE漏洞，我们尝试下该漏洞是否能够利用(https://github.com/0xConstant/CVE-2019-16113.git)

![image-20241209230155768](https://s2.loli.net/2024/12/09/GP7OC25TUtEaZHs.png)
